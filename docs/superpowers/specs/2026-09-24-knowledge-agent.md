# 软考资料知识库与智能体

## 目标与边界
在 `feat/soft-exam-v1` 的 Java 17 单体、Vue 管理后台和 uni-app 小程序中实现：管理员创建知识库、上传软考资料、审核发布，配置关联该知识库的学习智能体；学员选择智能体，连续提问，查看原文片段和 PDF 页码。

沿用 `docs/specs/soft-exam-v1.md`：只运营系统架构设计师；AI 通过 AiProvider 调用，不改变题库标准答案、Learning Engine 或权限；不引入微服务、MQ、向量数据库和付费测试依赖。

本次默认上传入口在管理后台；不自动将未审核资料公开，不增加学员私人上传。支持文本型 PDF、UTF-8 TXT、Markdown。图片/扫描 PDF 无文字时明确要求 OCR；混合 PDF 跳过无文字页并给出警告，不声称图片、表格版式或扫描文字已被理解。

## 方案
使用中文双字切分和英文词切分，将词项写入 PostgreSQL `tsvector`，通过 GIN 索引检索已发布文档。它是可运行的词法 RAG，而非向量语义检索；同义词召回能力有限。先形成上传到引用问答闭环，保持后续替换检索实现的边界。

原始资料通过独立可替换 KnowledgeFileStore 保存。默认本地私有目录，不使用现有 StorageProvider 的公开 URL。原文片段经鉴权 API 读取，不把磁盘路径或 API Key 返回前端。

## 数据与接口
- 知识库：考试、名称、说明。
- 文档：知识库、原文件名、SHA-256、页数、状态 REVIEW/PUBLISHED、警告、上传人；同一库内相同文件幂等去重。
- 分片：文档、真实页码、序号、原文、检索索引。按页分片，800 字符窗口、120 字符重叠。
- 智能体：名称、说明、辅导指令、关联知识库、启用状态。创建时默认停用。
- 会话和问答轮次：归属用户与智能体，保存问题、回答、引用快照和请求标识。
- 管理接口 `/api/v1/admin/knowledge/**`，现有 ROLE_ADMIN 保护。
- 学员接口 `/api/v1/ai/agents/**`，只开放启用智能体和已发布资料；会话必须属于当前用户。

上传同步执行、限定 20 MiB / 500 PDF 页 / 200 万提取字符；解析失败不写入假成功记录。分片与文档在一个数据库事务提交，存储失败或数据库失败不发布任何内容。发布与撤回均为显式操作。

## 回答规则
固定系统指令将历史记录和资料视为数据，而非系统命令。先检索后调用现有 AiService，复用配额与使用日志。没有有效命中时不调用模型，明确回答资料不足。答案引用只允许本次命中编号；缺少有效引用或出现不存在的编号时返回可核验的检索原文而非假装生成成功。

会话请求使用客户端生成的 UUID 幂等标识，重试成功轮次不再次调用模型；同一会话并发请求返回冲突。禁用智能体或撤回文档后新请求不再检索该内容。会话历史和引用不允许跨用户读取。引用快照属于用户已有会话；实时原文接口重新检查当前发布状态。

## 前端
后台提供知识库管理、上传、分片预览、发布/撤回、智能体配置和调试问答。小程序保留普通 AI 和题目讲解能力，新增资料智能体入口、历史会话、引用原文。所有页面显示加载、空、错误与配额耗尽状态，不放置假业务数据。

## 验证与限制
覆盖中文检索、跨页引用、扫描 PDF、错误编码、大小边界、文件存储、缺少证据、引用越界、未发布资料、会话越权和幂等请求。PostgreSQL 集成测试使用 Testcontainers，AI 使用测试替身。服务器执行 `mvn -B verify`；前端执行各自 `npm test`、`npm run typecheck` 和生产构建。

上线必须配置真实 AI Provider/API Key，并持久化知识资料目录与 PostgreSQL。自动化测试通过不等于已在用户服务器部署或完成真实模型、微信真机验证。
